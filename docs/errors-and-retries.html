Errors and retries

Every error the ledger returns is one of its own, wrapping Blnk's for your logs. Always compare with errors.Is, never on the message.

What each error means

ErrorMeansWhat to do
ledger.ErrInsufficientFundsthe source account can't cover ittell the customer; nothing moved
ledger.ErrDuplicatethis exact write already happened, appliedtreat as success; the existing entry comes back with it
ledger.ErrReferenceUsedthe reference holds something that didn't apply: a different transaction, or this one rolled backnothing moved under it; record again under a new reference, or investigate if you didn't expect it
ledger.ErrNotFoundno such account, entry or holdcheck the id
ledger.ErrUnbalancedFrom and To don't add up to the same amountfix the postings
ledger.ErrAlreadyReversednothing (or not that much) is left to reversenothing to do; pass a Ref to get your own reversal back on a retry
ledger.ErrHoldSettledthe hold was already captured, cancelled or expiredlook at what happened before acting again
ledger.ErrInvalidrefused before reaching Blnk: missing reference, negative amount, wrong ledger, …a bug in the caller; don't retry
ledger.ErrReadBackRecordAll applied, but reading the entries back faileddon't record it again; look the entries up by reference
money.ErrCurrencyMismatchan amount's currency doesn't match the account'sa bug in the caller
money.ErrUnknownCurrencya Money that was never set, or an unknown codea bug in the caller

References, in one rule

Build every reference from your own ids, with ledger.Reference:

CallReference
ledger.Reference("deposit", "paystack", paystackRef)deposit:paystack:ps_123
ledger.Reference("transfer", transferID)transfer:tr_42
ledger.Reference("payout", payoutID)payout:po_7

Never use a random value or a timestamp: a retry must produce the same reference, so Blnk can refuse to apply it twice.

When a split or batch fails partway

Blnk records a split (and a RecordAll batch) one part at a time. If a later part fails:

  1. You get the error (say ErrInsufficientFunds), but the earlier parts have already moved.
  2. Blnk refunds them from its background worker a moment later (about 200 ms). Until then they show in the accounts.
  3. The references stay used. Recording again with the same Ref returns ErrReferenceUsed; use a new one.

Get and GetByReference show such an entry as StatusRejected, even before the refund lands. Keep Blnk's worker running and monitored: if it's down, the earlier parts stay moved until it restarts.
