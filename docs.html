Build a wallet on Blnk

A practical guide to the ledger package, told through Oja, a wallet app serving customers in Nigeria: naira, dollars and bitcoin, from signup to month-end close.

By Otyang · github.com/otyang/humanblnk

Overview

humanblnk is an unofficial Go library over Blnk, the open-source double-entry ledger. Blnk gives you balances, transactions and a strict accounting core; this library turns them into the operations a wallet product actually has: top-ups, transfers, withdrawals, card holds, marketplace splits, escrow, currency exchange, statements and the back-office work behind them.

This guide follows Oja, a Nigerian wallet app. Ada keeps naira, dollars and bitcoin with Oja, pays friends and merchants, and saves for rent. Chidi Stores sells through Oja's marketplace. Every code sample on this page is compiled and run against the library's test suite.

Install and run Blnk

Import the module root for everything in one place, or the packages directly. They are the same types, so mix them freely; this guide uses ledger.

You need a Blnk Core to talk to. Locally, Blnk runs in Docker (server, worker, Postgres, Redis) and listens on http://localhost:5001; see Blnk's install guide. To try the library first with no setup at all, run the bundled walkthrough against the in-memory emulator:

Set up the service

Create one Service at startup and share it; it is safe for concurrent use. Depend on the ledger.Ledger interface (or a single namespace) in the rest of your code.

Money

Amounts are typed as decimal strings, exactly as the user entered them, and never pass through floating point. Every amount the service returns carries three forms:

FieldExample (₦1,250.5)Use it for
Value / JSON amount"1250.5"computing, storing, APIs: exact
Display / JSON display"1250.50"showing to people
PreciseAmount + Precision125050 × 100what Blnk stores: the integer in the smallest unit

Display follows a rule per currency: fiat and stablecoins are padded to their decimals; crypto is trimmed and cut, never rounded up, so a displayed balance can always be withdrawn in full.

Currencyamountdisplay

Typing more decimals than a currency has ("100.567" NGN) is rejected before anything reaches Blnk, as are exponents like 1e3. Currency symbols and thousands separators belong in your front end, which knows the user’s locale.

References and retries

Every movement takes a Reference, and Blnk accepts each reference once. That makes every call safe to retry: send the same request again and you get the original transaction back with Replayed: true instead of moving money twice.

  • Generate the reference once, when the user taps "Send", and store it with the pending request, so a retry after a timeout reuses it.
  • For money arriving from a provider, use the provider’s reference (Paystack’s, a blockchain txid:vout), so a repeated webhook can’t credit twice.
  • The same reference with a different amount, account or kind of movement fails with ErrDuplicateReference: a real conflict to investigate, not to retry.
  • Pending().Confirm and Cancel carry no reference, so the client never repeats them blindly after a timeout: look the transaction up before trying again.

Accounts and the chart of accounts

Customer accounts are where users’ money lives. System accounts, named with @, are the other side of every entry and are what finance reconciles. Blnk creates each system account on first use, per currency.

AccountTypeRole
@PaystackClearing (any @<Provider>Clearing)Asset / liabilityMoney a provider collected for you, or paid out for you, not yet settled with your bank
@FeeIncomeIncomeEvery fee
@BankOperatingAssetYour bank account
@ProviderFeesExpenseFees providers keep at settlement
@FXPoolPositionYour open position per currency from exchanges
@MerchantPayableLiabilityCaptured card payments owed to the card network
@SuspenseSuspenseMoney that arrived but can’t be matched to a customer yet
@AdjustmentsEquity / expenseCounterparty of approved manual corrections

Blnk debits the source and credits the destination, so asset and expense accounts run negative and liability and income accounts run positive. Account Kind tells them apart: customer, system, pot or escrow.

Onboard a customer

Ada signs up and gets naira, dollar and bitcoin accounts in one call.

This creates a Blnk identity and one account per currency. With ExternalID set (your own user id), calling it again after a timeout returns the same accounts and opens any new currencies, so signup is safe to retry. The tier metadata drives limits and pricing.

Read a balance

Available is what the app should let Ada spend: the balance minus money reserved by card holds and pending withdrawals.

Freeze, unfreeze and close

Accounts().Close refuses while anything is pending, moves any remaining balance to SweepTo, then marks the account closed for good. A frozen account can still be closed.

Top up through Paystack

Paystack confirms a payment; credit Ada exactly once.

AccountDebitCredit
@PaystackClearing150,000.00
@FeeIncome2,000.00
Ada · NGN148,000.00

The fee leg and the customer leg post together. Paystack now owes you ₦150,000 until it settles.

Set Pending: true to hold a deposit for checks (say, a first large top-up) and approve it later with Pending().Confirm.

Send money to a friend

Ada sends Tunde her share of the rent, seeing the fee before she confirms.

AccountDebitCredit
Ada · NGN12,510.00
Tunde · NGN12,500.00
@FeeIncome10.00

A quote runs the same checks as the real transfer (funds, limits, frozen accounts, fee) without moving money, so what Ada confirms is what she is charged.

Withdraw to a bank account

Card payments

Authorise first, capture what the merchant actually charges, release the rest.

AccountDebitCredit
Ada · NGN17,250.50
@MerchantPayable17,250.50

Only the captured amount posts. The rest is released back to Available.

Exchange currency

Ada converts dollars to naira at the rate you quoted.

AccountDebitCredit
Ada · USD101.00
@FXPool · USD100.00
@FeeIncome · USD1.00
@FXPool · NGN153,240.00
Ada · NGN153,240.00

Both legs post in one atomic batch. The pool balances are your open position per currency.

Give Buy instead of Sell to land an exact amount (“receive exactly ₦100,000”). The bought amount rounds down and a computed sell amount rounds up, so rounding never costs you.

Crypto

Exact satoshi accounting, with display that never overstates a balance.

Crypto uses each chain’s smallest unit (satoshi, wei), so ledger balances match the chain exactly. For stablecoins on several chains, note that decimals differ by chain (USDT is 6 on Tron and Ethereum, 18 on BNB Chain): keep one precision per ledger currency and convert at the edge, or give each chain its own currency code.

Each escrow is its own account, so what’s still held is simply its balance, and Blnk itself refuses to release more than is left.

Disputes and chargebacks

Freeze the disputed money until the case is decided.

Opening a dispute places a hold in the seller’s account pointed back at the payer, so the money can’t be spent while it is investigated. For a payment that carried a fee, the library disputes the leg that paid the seller, never the fee.

Refunds

Return part of a payment when an item is out of stock.

Partial refunds are linked to the original with meta_data.refund_of, and they are added up before each new one, so over-refunding is refused, and a retried refund replays instead of counting twice. A transaction can be reversed in full with Refund or in parts with RefundPartial, not both. If refunds for the same transaction can run concurrently, serialise them (one worker or a row lock).

Savings pots and standing orders

Ada saves for rent automatically every month.

A pot is a sub-account in the same currency and identity, with an optional goal. Blnk has no native recurrence, so a standing order is a set of scheduled transfers sharing meta_data.recurring_reference; calling Schedule again with the same input is safe.

Payroll

A merchant pays its staff in one batch.

Atomic makes the batch all-or-nothing. Up to 10,000 transfers per batch; Async processes in the background with the outcome sent as a bulk_transaction.* webhook.

Fees

Every chargeable call (deposit, withdrawal, transfer, exchange, standing order, bulk item and their quotes) must say what it charges, so a fee can never be forgotten. Either pass Fee on the call (ledger.NoFee for free), or set Config.Fees to price them centrally:

FeeRuleExampleMeaning
Percent"1.5"1.5% of the amount
Fixed"10"flat ₦10 (in the transaction’s currency)
Min, Max"10", "2000"floor and cap
Tiers≤ ₦5,000: ₦10, above: 0.1%bands by amount
RoundingRoundHalfUpor RoundUp / RoundDown

A fee is always in the transaction’s own currency. To price “$0.50 everywhere”, convert inside your function with r.Convert(ledger.Amount("0.50", "USD"), rate, ledger.RoundUp). A fee passed on the call always wins over the function, which is how promotions and waivers work.

Limits and KYC tiers

Per-tier caps, checked before any money moves.

Limits apply to money leaving customer accounts: transfers, withdrawals, holds, splits, exchanges and escrow (bulk batches are not checked). A pending hold counts while held and comes back if cancelled. Days and months reset in Config.Location.

Statements

A downloadable month for Ada, checked against the ledger.

The statement lists posted entries only, dated by when they took effect, so a standing order appears on the day it posted. The closing balance is checked against Blnk’s own balance at the end of the period: a statement that doesn’t add up is an error, never a wrong document. Fees appear as their own lines, as on a bank statement.

Trial balance

One call to prove the books add up.

In double entry every currency nets to zero. Run this nightly and alert when Balanced is false; CustomerFunds is the total you owe customers, the figure your safeguarding account must cover.

Provider settlement

Clear Paystack’s receivable when the money reaches your bank.

Each provider has its own clearing account, so after recording settlements its balance is exactly what that provider still owes you (or you owe it) and can be ticked off against its report. Use SettlementPayout for payout providers you prefund.

Unidentified money

Park money you can’t match yet; allocate it once support knows whose it is.

Manual corrections

Corrections with a second pair of eyes.

Every adjustment records its reason, requester and approver in metadata, and the same person can’t do both.

Balance alerts

Get told when a float runs high or low.

Reconciliation

Match Paystack’s report against the ledger.

Without RuleIDs, a rule matching reference, currency and amount exactly is created once and reused. Up to 10,000 records go inline; larger exports upload as a CSV with File. Blnk reports counts, not the matched lines.

Payments that carried a fee are stored by Blnk as legs (ref-1, ref-2), so they don’t match a provider line one-to-one. Try Strategy: "one_to_many" with GroupingCriteria: "parent_transaction", and check the counts against your own Core version before relying on them.

Webhooks

React to what happens in the ledger.

With Secret set, signatures (X-Blnk-Signature, HMAC-SHA256 of timestamp.body) and a five-minute timestamp window are checked; without it nothing is verified, so make sure it is set in production. Blnk delivers at least once and retries on errors, so make handlers idempotent, for example keyed on e.Receipt.TransactionID plus e.Name. An expired hold arrives as transaction.void.

Logging, metrics and tracing

Observer receives every call’s name, context and error, which is all you need for metrics or one OpenTelemetry span per call. Business refusals (insufficient funds, limits) log at Warn, failures at Error.

Testing your app

Fast tests with no Docker, using the real request code.

ledgertest is an in-memory Blnk Core: your tests run the real Service code, so they exercise the same requests production sends. It behaves like Core 0.15 where that matters (fee legs, stored ids, required descriptions) and lets you move time forward to expire holds and run scheduled transfers. Blnk versions and known limits

Needs CoreFeature
0.8.4Historical balances (BalanceAt, Statement), global webhooks
0.10.0Inline reconciliation
0.13.2Filters: history, account search, limits, trial balance, ExternalID
0.14.1Auto-capture with CaptureAt (inflight commit queue enabled)
0.14.2ConfirmMany / CancelMany
0.15.0Structured error codes (older versions fall back to HTTP status)
0.15.3CoreDryRun quotes, refund descriptions
  • Fee legs. A movement with a fee is stored as legs (ref-1, ref-2) with no parent record. The library rebuilds the parent for lookups and retries, and disputes or refunds pick the recipient’s leg, but raw Blnk queries and reconciliation see legs. A pending one is confirmed in full (or one leg at a time), never partially.
  • System account ids. Blnk stores @FeeIncome-style accounts by balance id; receipts and history show the id, statements show the name.
  • Concurrent partial refunds of one transaction can both pass the remaining-amount check; serialise them.
  • Balance alerts fire after every update while the condition holds; debounce them.
  • Dry-run quotes need Core 0.15.3; older Core ignores dry_run and posts, which is why CoreDryRun is off by default.
